Set up Fitto

About 20 minutes. You'll set a few secrets with the GitHub CLI from your own terminal. Never paste secrets into chats, issues or commits. The full guide, with every option, is SETUP.md.

Use repository secrets, not environment secrets. In the web UI: Settings → Secrets and variables → Actions → Repository secrets → New repository secret. Secrets added under Environments → github-pages are invisible to Fitto's workflows. gh secret set NAME (without --env) always creates a repository secret; check with gh secret list.

1. Profile

Copy profile.example.yaml to profile.yaml (git-ignored), fill in your skills, locations, salary floor, dealbreakers and CV text, then store it as a secret:

gh secret set FITTO_PROFILE < profile.yaml

2. State key

This encrypts everything Fitto remembers. Keep a copy in your password manager.

pnpm fitto keygen | gh secret set FITTO_STATE_KEY

3. Email

Set FITTO_EMAIL_TO, then either SMTP (for example a Gmail app password) or a Resend key:

gh secret set FITTO_EMAIL_TO
gh secret set SMTP_HOST --body smtp.gmail.com
gh secret set SMTP_PORT --body 465
gh secret set SMTP_USER
gh secret set SMTP_PASS          # Gmail app password
# or
gh secret set RESEND_API_KEY

4. Smarter scoring (recommended)

Without an API key, Fitto uses a free keyword scorer: rough scores, no "why it fits" summaries and no drafts. Add one LLM key and add some prepaid credit with the provider. If both are set, OpenAI is used unless you set FITTO_LLM to anthropic.

ProviderGet a keySet itDefault model and cost
OpenAI (default)platform.openai.com/api-keysgh secret set OPENAI_API_KEYgpt-4.1-mini, a few cents a day
Claudeplatform.claude.com → API keysgh secret set ANTHROPIC_API_KEYclaude-haiku-5-5, a little cheaper
 
gh variable set FITTO_LLM --body anthropic            # prefer Claude when both keys are set
gh variable set FITTO_MODEL --body claude-sonnet-5-5   # optional: more careful, about 20× the cost

Each run scores up to 40 jobs (best keyword matches first) and leaves the rest for the next run.

5. Your encrypted job list on this site

Pick a long passphrase of at least 12 characters; shorter ones make the site deploy publish docs only. A generated one is best. Save it in your password manager first, because you'll type it here. The workflow encrypts your matches with it, and only the ciphertext is published.

pnpm fitto keygen                        # copy the output into your password manager
gh secret set FITTO_SITE_PASSPHRASE      # paste it when prompted

Then open My jobs and enter the same passphrase. Tick "Remember on this device" only on devices you trust. Changing the passphrase takes effect on the next run.

6. Send jobs to The Next Chapter (optional)

Fitto never sends anything on its own. On My jobs, tick the jobs you want and press Send selected to The Next Chapter. You'll be asked to confirm the count once. Pick a route under Settings:

RouteWhat you needHow it works
GitHub Action (default) gh secret set TNC_API_TOKEN in the repo, plus a fine-grained GitHub token pasted into the site The site starts one fitto-tnc run with the opaque ids you selected. The workflow submits the jobs one by one and records Sent, Accepted or Failed. The site shows the result after it refreshes.
Direct API Your The Next Chapter token pasted into the site Your browser posts each job URL straight to The Next Chapter. This currently doesn't work, because The Next Chapter doesn't allow browser requests (CORS) yet. The site detects this and offers a one-click switch to the GitHub Action route.

Create the fine-grained GitHub token

  1. Open github.com/settings/personal-access-tokens/new.
  2. Name it "Fitto site" and give it a short expiry (for example 90 days).
  3. Under Repository access, choose Only select repositories → adamsdenniskariuki/fitto.
  4. Under Repository permissions, set Actions: Read and write and leave everything else at "No access". (Metadata: Read-only is added automatically.)
  5. Generate it, then paste it into My jobs → Settings. It is stored in this browser only and sent only to api.github.com.

Is Direct mode available yet?

You can check without submitting anything. On My jobs (other pages block outside connections on purpose), press F12 and run this in the Console. It sends no token, so nothing can be created:

fetch("https://thenextchapter.dev/api/v1/submissions", {
  method: "POST", headers: { "Content-Type": "application/json" }, body: "{}",
}).then(r => console.log("CORS OK, status", r.status))
  .catch(e => console.log("Blocked by CORS:", e.message));

"Blocked by CORS" means you should keep using the GitHub Action route. "CORS OK, status 401" means Direct mode will work.

With that permission, the token can start or cancel workflow runs in the fitto repository and nothing else. Workflow inputs on a public repository are public, so the site sends only opaque job ids, never URLs or titles. Revoke the token at any time from the same settings page.

7. Run it

gh workflow run fitto.yml                   # daily run now (otherwise every morning)
gh workflow run fitto.yml -f dry_run=true   # dry run: nothing is sent or saved

Troubleshooting

Run logs show counts only: Actions → fitto → latest run → Run Fitto.

You seeFix
"Dry run (… FITTO_PROFILE / FITTO_STATE_KEY not set)"The secrets are missing or are environment secrets. Re-add them as repository secrets.
scoring (heuristic)No LLM key is set (step 4).
HTTP 401 (invalid_api_key) / (authentication_error)Wrong or revoked key. Create a new one and run gh secret set again.
HTTP 429, insufficient_quotaAdd billing credit. Deferred jobs are scored on later runs.
No emailCheck spam and the SMTP secrets (Gmail needs an app password, port 465).
pages fails: "passphrase must be at least 12 characters"Set a longer FITTO_SITE_PASSPHRASE (step 5).
Wrong passphrase on My jobsAfter changing it, wait for the next pages run to finish.
